1. One-Line Summary
- MenuMind is an autonomous cafe operations agent for the Google Antigravity Hackathon.
- It turns messy signals such as supplier messages, weather, local events, competitor moves, and crises into safe menu, staff, approval, and notification actions.
- Core loop: observe -> reason with Gemini/fallback -> policy guard -> execute tools -> persist state -> show trace/result in UI -> optionally dispatch externally through Make.

2. Hackathon Goal
- Target: Google Antigravity Hackathon, Challenge 1: autonomous content-to-action / agentic app workflow.
- The demo must show input -> insight -> action -> simulation/result with clear agent trace.
- Mobile app/prototype is mandatory; current safest APK route is Capacitor around the frontend after backend deployment.

3. Product Promise
- Not a chatbot and not a static if/else demo.
- The restaurant owner can enter a freeform real-world signal:
  "A marathon is happening near G-13 with warm weather. What should my restaurant do?"
- MenuMind should reason about demand, health-conscious customers, hydration, stock, staffing, promotions, competition, and ethical limits.
- The result should include insight, impact, primary action, recommended actions, menu changes, messages, approvals if needed, and audit trace.

4. Main Stack Today
- Backend: FastAPI + SQLAlchemy + Pydantic.
- Local DB: SQLite by default via `backend/menumind.db`.
- Optional cloud DB: `DATABASE_URL` supported, but Supabase schema must be aligned before using it as the backend database.
- Planner: Gemini REST API through `backend/llm_adapter.py`, default model `gemini-2.5-flash`.
- Safety fallback: deterministic planner remains as honest resilience when Gemini/API times out.
- Frontend: Next.js dashboard in `frontend/src/app` and `frontend/src/components`.
- External automation: Make.com webhook dispatch from backend when configured.
- Weather: Open-Meteo no-key weather context in `backend/weather.py`.

  - `adjust_item_price`

  - `extend_prep_time`
  - `create_approval`
  - `send_staff_alert`
  - `create_customer_notice`
  - `estimate_revenue_impact`
  - `crisis_response`
- Gemini is never allowed to execute arbitrary code.
- New actions must be added to the registry with validation.

10. Safety and Ethics Guardrails
- Crisis signals require approval.
- Price increases above 15% require approval.
- Public-stress situations must not trigger surge pricing:
  - heatwave
  - marathon/event crowd
  - flood
  - strike/hartal
  - blocked roads
  - emergency/protest
- If Gemini proposes upward pricing during public stress, backend converts it to promotion.
- If supplier disruption exists but buffer stock is enough, agent can extend prep time rather than hide the item.
- Fallback planner is allowed only as resilience; it must be trace-labeled as fallback.

18. WebSocket Decision
- No real WebSocket is implemented.
- Current behavior: frontend polls every few seconds for updates.
- WebSocket difference:
  - polling = browser asks backend repeatedly
  - WebSocket = backend pushes instantly to browser
- WebSocket is nice but not required for the hackathon demo.
- Adding it means extra deployment/debug work and is lower priority than APK/deployment stability.

25. Clean Demo Scenarios
- Marathon/event:
  - Input: marathon near G-13 with warm weather.
  - Expected: promote hydration/healthy cold drinks, prepare staff/stock, produce strategic advice.
- Supplier shock:
  - Input: chicken delivery failed.
  - Expected: update availability or prep time based on stock, alert staff, suggest substitute.
- Heatwave:
  - Input: 43C/44C heatwave near restaurant.
  - Expected: promote Iced Mint Lemonade or cold drinks, staff prep alert.
- Competitor price attack:
  - Input: nearby cafe cuts prices.
  - Expected: margin-aware promotion, not reckless price war.
- Crisis guardrail:
  - Input: flood/strike/road blockage.
  - Expected: no surge pricing, approval required, customer/staff message.
- Contradiction:
  - Input: supplier says unavailable but inventory has buffer.
  - Expected: conserve/extend prep time instead of unnecessary hiding.
