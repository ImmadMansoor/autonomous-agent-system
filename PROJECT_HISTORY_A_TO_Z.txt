1. Project Snapshot
- Product: MenuMind, an autonomous cafe operations agent.
- Hackathon target: Google Antigravity Hackathon, Challenge 1: autonomous content-to-action / agentic app workflow.
- Core promise: turn messy business signals into safe cafe actions, not just chatbot advice.
- Core loop: raw signal -> planner -> policy guard -> tool execution -> database mutation -> trace/UI result.
- Example signal: "A marathon is in G-13 now; what should my restaurant do?"
- Example real result: Gemini recommends promoting Iced Mint Lemonade, alerts staff, and updates menu state.

2. Original Goal
- Build a demo that proves autonomous reasoning and execution for small food businesses.
- Signals can come from supplier messages, weather, local events, competitor pricing, or crisis alerts.
- The agent must show insight, action, simulation/result, and traceability.
- Mobile app/prototype is mandatory for the hackathon.

3. Early Architecture Debate
- Earlier plans considered Supabase + Make.com + FlutterFlow as a low-code stack.
- Gemini and other models argued Supabase/Make would show cloud workflow proof.
- The local build initially felt fake because some generated logic looked like static if/else or demo presets.
- The final decision was not to restart from scratch, because the local FastAPI + React system became real and recoverable.
- Current position: keep FastAPI/React as the main product, use Make/Supabase only as optional cloud proof.

4. Current Runtime Architecture
- Backend: FastAPI, SQLAlchemy, Pydantic.
- Database: SQLite by default via `backend/database.py`; optional `DATABASE_URL` exists but Supabase schema is not aligned yet.
- Agent pipeline: `backend/agent.py`.
- Planner: `backend/llm_adapter.py`.
- Tools: `backend/tools.py`.
- Frontend: React/Vite in `frontend/src/App.jsx`.
- Styling: `frontend/src/index.css`.
- PWA files: `frontend/public/manifest.json`, `frontend/public/sw.js`.

5. Main Backend Flow
- `POST /signals` stores a raw business signal.
- `POST /agent/run/{signal_id}` starts the autonomous pipeline.
- Pipeline snapshots menu state before planning.
- Planner returns structured `AgentPlan`.
- Policy guard modifies or holds risky actions.
- Tools execute allowed changes.
- Pipeline snapshots menu state after execution.
- UI reads trace, before/after diff, notifications, approvals, and final decision.

6. Important API Endpoints
- `GET /health`: backend status, planner mode, Gemini model, timeout.
- `GET /menu`: current menu state.
- `POST /signals`: create signal event.
- `POST /agent/run/{signal_id}`: run agent.
- `GET /agent/runs/{run_id}`: final run record.
- `GET /agent/runs/{run_id}/trace`: audit trace.
- `GET /menu/before-after/{run_id}`: state diff.
- `GET /approvals`: pending/handled approvals.
- `POST /approvals/{id}/approve`: approve held action.
- `GET /notifications`: staff/customer simulated messages.
- `GET /signals/scenarios`: clean preset signals.
- `POST /demo/reset`: reset local demo state.

7. Database Tables
- Local SQLAlchemy tables:
  - `menu_items`
  - `signal_events`
  - `agent_runs`
  - `agent_trace`
  - `approvals`
  - `notifications`
- Local `menu_items.id` is a string such as `chicken_wrap` or `iced_lemonade`.
- Local menu fields include `base_price`, `current_price`, `is_available`, `is_promoted`, `stock_level`, `margin_pct`, `prep_time_min`.

8. Planner Behavior
- Gemini is the preferred real planner when `GEMINI_API_KEY` exists.
- The project now uses Gemini REST `generateContent`, not the deprecated `google.generativeai` SDK.
- Default model: `gemini-2.5-flash`.
- Default timeout: 35 seconds.
- Safety fallback remains intentionally, but it is clearly labeled and is not allowed to pretend to be Gemini.
- The frontend no longer contains hardcoded demo planning logic.

- Future tools should be added to the registry; do not let Gemini execute arbitrary code.

11. Safety Rules
- Crisis signals require approval.
- Price increases above 15% require approval.
- Public-stress situations such as heatwaves, marathons, strikes, blocked roads, emergencies, or protests must not raise prices.
- Public-stress upward price actions are converted into promotions.
- Supply shocks with buffer stock should extend prep time instead of disabling the item.
- Routine supply, weather, competitor, and event actions may execute automatically when safe.

17. Recommended Make Integration
- Preferred Make -> MenuMind flow:
  1. Make Custom Webhook receives a supplier/weather/event/competitor signal.
  2. Make HTTP module calls public/deployed MenuMind `POST /signals`.
  3. Make HTTP module calls `POST /agent/run/{signal_id}`.
  4. Make reads `GET /agent/runs/{run_id}`, `/trace`, `/menu/before-after/{run_id}`, `/notifications`, or `/approvals`.
- Make cannot call `localhost`; expose FastAPI through deployment or a demo tunnel.
- Stable inbound payload:
  - `source_type`: supplier/weather/competitor/event/manual.
  - `raw_text`: the messy signal text.
  - Optional metadata can stay in Make/Supabase logs.
- For hackathon demo, local FastAPI remains the real autonomous agent. Make/Supabase can be shown as external automation proof.

18. Mobile App / APK Requirement
- Challenge notes say a working prototype with mobile app is mandatory.
- Current app is mobile-first React and has PWA support.
- Best 48-hour APK path: Capacitor Android wrapper around existing Vite app.
- Do not rewrite in Expo or FlutterFlow now; that creates too much risk.
- PWA remains backup evidence, not the strongest APK proof.
- `API_URL` is configurable through frontend `VITE_API_URL` because `localhost` inside an APK means the phone, not the laptop.
- For Android emulator use `http://10.0.2.2:8000`.
- For physical phone use laptop LAN IP, e.g. `http://192.168.x.x:8000`, same Wi-Fi.

19. Clean Demo Scenarios
- Supply shock:
  - Signal: Roman Urdu chicken delivery failure.
  - Expected: hide Chicken Wrap if stock low, promote Beef Wrap, staff alert.
- Heatwave:
  - Signal: Islamabad 44C heat advisory.
  - Expected: promote Iced Mint Lemonade, staff prep alert.
- Competitor price attack:
  - Signal: competitor drops burger price.
  - Expected: avoid destructive price war, promote/discount within safe limits.
- Crisis guardrail:
  - Signal: strike/blocked roads/delivery freeze.
  - Expected: no surge pricing, approval required.
- Contradiction:
  - Signal: supplier says unavailable but inventory buffer exists.
  - Expected: conserve availability or extend prep time.
- Marathon/event:
  - Signal: G-13 marathon or hot event near cafe.
  - Expected: promote healthy cold drink, staff alert, strategic advice.

  `cd frontend`
  `npm install`
  `npm run dev`
- Health:
  Open `http://127.0.0.1:8000/health`.
