1. Current Product
- MenuMind is an autonomous cafe operations agent developed for the Google Antigravity Hackathon, Challenge 1 (content-to-action agentic workflow).
- Core Loop: Ingests messy, raw input signals (weather, web, competitor data) -> analyzes via Gemini REST reasoning pipeline -> checks deterministic policy safety guardrails -> executes automated cafe tool operations -> records DB mutations -> generates trace logs -> displays rich, visual UX with spoken summaries.
- Key Value: Pauses high-risk or suspicious actions (like crisis pricing anomalies) for human approval while executing routine tasks (such as supply shocks) automatically.

2. Current Stack & Repository Layout
- Root Directory Structure:
  - `frontend/` - React Vite public marketing landing website ("Shaping Cafes of tomorrow"), deployed automatically via Vercel.
  - `backend/` - FastAPI backend server and core Gemini agent orchestration pipeline.
  - `desktop-app/` - Next.js production operations dashboard wrapped in Tauri for portable desktop systems (and isolated from the landing page).
  - `website/` - Clean Vite React source blueprint copy of the public landing site.
  - `mobile/` - Dedicated mobile Android platform source and compiled releases:
    - `mobile/MenuMind-LiquidGlass/` - React Native / Expo codebase with native Kotlin Compose UI elements.
    - `mobile/releases/android/MenuMind-release-V49-current.apk` - The final, fully validated mobile release APK.
    - `mobile/build-mobile-apk-fast.ps1` - Dynamic virtual-drive mounting build compiler.
- Live Web URLs:
  - Live Frontend (Marketing website): Vercel - https://menumind-nu.vercel.app
  - Live Backend: Render - https://menumind-backend.onrender.com

3. Core Backend Files
- `backend/main.py`: Main API router (handles authentication, settings updates, metrics ingestion, audit logs, and whitelists Tauri CORS).
- `backend/agent.py`: Observe-Reason-Policy-Execute-Finalize pipeline driving cafe automation.
- `backend/llm_adapter.py`: Gemini planner, dynamic settings-driven model routing, and deterministic safety fallback protection.
- `backend/tools.py`: Tool registry and café state mutations (stock counts, promotion toggles, alerts).
- `backend/models.py`: SQLAlchemy database models.
- `backend/schemas.py`: Pydantic schema validation contracts.

4. Core Frontend (Landing Website) & Operations Console Files
- `frontend/src/index.css`: Root Tailwind CSS v4 styling sheet importing Outfit/Inter Google fonts and defining custom glass-card designs.
- `frontend/src/App.tsx`: Marketing landing page UI showcasing dynamic metrics, platform statuses, accesses, and hover interactions.
- `frontend/vite.config.ts`: Vite compilation setup utilizing react() and tailwindcss() plugins.
- `desktop-app/src/app/layout.tsx`: Root Next.js console HTML shell with theme prevention script and Error Boundary.
- `desktop-app/src/lib/api.ts`: API client featuring robust offline fallbacks (`optionalRequest`) for console demo resilience during cold-starts.
- `desktop-app/src/app/planner/page.tsx`: Live Operations Board showing console task cards in Now/Next/Approvals/Done stages.
- `desktop-app/src/app/analytics/page.tsx`: Intelligence page with a dynamic business impact console dashboard.
- `desktop-app/src/components/ErrorBoundary.tsx`: isolating boundary catching Next.js React card failures gracefully.

5. Mobile (React Native + Native Kotlin Compose)
- The mobile system under `mobile/MenuMind-LiquidGlass/` implements a custom, Nothing OS-inspired Liquid Glass UI using Jetpack Compose components.
- **Theme Synchronization Fix (V49):** Solved the critical lag where the liquid bottom navigation bar remained styled for the old theme until a user slid it. Keyed the native `LiquidTabBar` component by active theme state in React Native, and wrapped the native tabs container in a Compose `key(isDark)`. This forces the subtrees to remount immediately when the dark/light mode toggle is pressed.
- **PixelCopy Attachment Guard:** Fixed a physical-device crash where early background sampling threw `Window doesn't have a backing surface!`. Added check conditions in `LiquidTabBarManager.kt` and caught `IllegalArgumentException` so initial frames skip safely before attachment completes.
- **Aesthetic Polishes:** Tuned the kyant blur, increased PixelCopy backdrop bitmap opacity, and layered a smoky milk tint to turn the nav capsule into a frosted glass body rather than an empty outline.

6. Desktop Application (Tauri)
- The Tauri desktop app codebase under `desktop-app/` maps perfectly to the Next.js layouts, optimized for quick desktop execution.
- **CORS Whitelisting:** Whitelisted `"http://tauri.localhost"` and `tauri.localhost` in the FastAPI CORS middleware (`backend/main.py`) to permit desktop-to-backend socket connections.

7. Web Resiliency & Flash-On-Load Toggles
- **Pre-Render Theme Injection:** The user wanted zero latency in dark mode loading. Added a lightweight inline JS block in the root layout head (`layout.tsx`) that checks `menumind_theme` from `localStorage` immediately, applying the `.dark-theme` styling class *before* the React hydration cycle begins to eliminate jarring white flashes.
- **Offline API Fallbacks:** Created an robust `optionalRequest` wrapper in `api.ts` which populates all pages (operations, menu, statistics, logs, settings) with high-fidelity mock data if the Render backend API is unreachable or waking up, ensuring zero dashboard crashes during live judge presentations.

8. Gemini Reliability & Dynamic Routing
- Implemented real backend routing in `llm_adapter.py` based on the user's saved Decision Speed preference:
  - **Fast Speed:** Maps to `gemini-2.5-flash` for high speed/low latency.
  - **Balanced Speed:** Maps to `gemini-2.5-pro` for balanced analytical depth.
  - **Thorough Speed:** Maps to `gemini-3-flash-preview` for high-depth strategic suggestions.
- Preserved a deterministic safety fallback planner that takes over if Gemini REST APIs suffer network timeouts or quota exhaustion, guaranteeing a functional live demo.
- Default Auto-Approve threshold normalized to `70%` instead of legacy floating-point indicators (`0.7`).

9. Build & Space Compiler Optimization
- Compilation path: `mobile/build-mobile-apk-fast.ps1`.
- Due to deep nested node directories and parent folder space bugs (e.g. "Google Hackathon"), compiling React Native Skia on Windows frequently triggers C++ compiler crash limits (`MAX_PATH`).
- The PowerShell script dynamically mounts the workspace to a virtual drive `M:\` using `subst`, executes compile/clean Gradle tasks with an increased 4GB heap size, and automatically unmounts the virtual path on termination.

10. Clean-Up & Git Hygiene
- **Excluded Old Payload:** Removed and ignored all redundant historical APKs (saving 300MB+ storage), experimental `debug.keystore` credentials, and root-level binary node shortcuts (`vite`, `semver`, `nanoid`, `rolldown`).
- **Target Folders Ignored:** Ensured Rust compile directories (`/target/` and `/gen/`), Expo caching directories (`.expo/`), and Android build products are securely ignored to maintain a lightweight Git repo.
